## Why first-run 32/32 kept happening

The method that worked: **pin the math in numpy against transformers hidden
states BEFORE writing any C** (`--l0check` in each oracle generator). Every
architectural subtlety was caught at the numpy stage at float precision, not
debugged in C at token level: Qwen3's pre-RoPE per-head norms (2e-7), OSS's
sink-in-softmax (1.3e-7), V4's *adjacent-pair* rotate_half variant (a third
rope flavor — caught as a 0.28 diff, fixed to 9.3e-8) and its 20-iteration
Sinkhorn (1.1e-7).

   163,584 vocab → 163,328 merges recovered, 0 orphans, 1.1 s) + K2

   official chat_template.jinja (committed fixture rendered by real jinja2),
   K2 tool-call parsing, family-aware streaming holdback.
3. **Stops (9af18c0):** found a latent blocker — the engine hardcoded
   `<|endoftext|>`; served K2 would have armed ZERO stop tokens (#298 class).
   EOS marker table + family-aware serve filter, GLM provably bit-identical.
4. **Integration proof (0b596c7):** DSv3-arch + K2-tokenizer tiny model
   through the real mux serve protocol: READY→SUBMIT→DATA→DONE with
   `[stop] 2 stop tokens: [EOS] <|im_end|>`.

What remains for real K2 is only the ~515 GB weight conversion (disk-bound).
